# ekit 0.6.0: forward baseline (brownfield: accept the past, hold the future)

Status: **implemented** in ekit 0.6.0 / kit 0.6.0 (golden `fastapi-jinja` 1.0.1, unchanged).
Covered by `tests/test_ekit_060_forward.py`; 279 tests in total pass. **Not yet run against a live
Spec Kit + OpenCode install.**

## 1. Why

0.5.1 let a brownfield repository record `Gap`s instead of failing. The first real adoption showed that
this still asks the wrong question on day one: the agent was made to assess the whole legacy code
against 20-odd NFRs, could not honestly name a ticket for each gap, **invented ticket ids** to satisfy
`Gap`, and the gate still blocked on skeleton files and conformance rows for code nobody was changing.
The baseline is a standard for what we build next. In an adopted repository it now applies **forward**:
existing code is accepted as-is; new features and change requests meet the constitution and the baseline
for the code they touch. The only day-one requirement is **pipeline readiness**: what red and green need.

## 2. What changed

- **Pipeline paths.** Profiles may declare `layout.pipeline_paths` (fastapi: `pyproject.toml`, `uv.lock`,
  `.python-version`, `tests/unit`, `tests/acceptance/conftest.py`, `.gitignore`; springboot, react: build
  file, wrapper/pin, test config; jinja and vanilla: none). In brownfield only these are errors
  (additive, nothing existing is touched); other `required_paths` are not reported (one info line per profile).
- **Git is required in brownfield.** Red and green evidence are commits; unusable git is an error (same cause and fix text as before).
- **`Inherited`** conformance status: existing code, not assessed or not yet meeting the NFR, accepted
  as-is. No evidence, no ticket. Info in brownfield; error in greenfield. `Gap` is unchanged.
- **Snapshot is optional.** `docs/engineering/baseline-conformance.md` is only written on request
  (`/speckit.esdlc.baseline snapshot`). An applicable NFR without a row is info.
- **Ratchet.** `ekit baseline enforce <NFR-ID>... --reason "..."` (a person; denied to the agent) appends to
  `.ekit/baseline-enforced.yaml` (`id`, `by`, `at`, `reason`). An enforced NFR needs a row `Addressed`, `N/A`
  or `Waived` with an ADR; `Inherited`, `Gap`, a deferral or no row is an error, and so is a missing file.
  One way: no un-enforce command; removal is a hand edit that should come with an ADR.
  `ekit baseline status` lists enforced NFRs.
- **Constitution lock.** `ekit constitution lock` (a person; denied to the agent; brownfield only) writes
  `.ekit/constitution.lock.yaml` with the sha256 of principles V–VIII, plus `by` and `at`. I–IV are always
  compared with the kit template. V–VIII are compared with the lock when there is one, else with the kit
  template. The constitution template text is unchanged (a test still pins I–VIII).
- **Duplicate NFR rows** in a conformance table are an error (`<NFR>: N rows in <file>; keep one`), in both modes.
  Before, the last row silently won.
- **Report folders.** Before any profile command ekit creates `<profile root>/reports/` and the parent of
  `bdd.report` (Windows: `pytest --cucumberjson=reports/...` crashed with `FileNotFoundError`).
- **Pin file encoding.** PowerShell 5.1 `echo 3.12 > .python-version` writes UTF-16 LE with a BOM;
  `Out-File` / `Set-Content` may write a UTF-8 BOM. `profile.environment` reads the pin robustly and
  reports `<pin> is UTF-16 | UTF-8 with BOM (PowerShell redirect?); rewrite it with `uv python pin 3.12``
  (other runtimes: rewrite as plain text without a BOM). A version mismatch shows odd pins with `repr()`.
- `ekit context` prints `mode:`. Prompts: the baseline command (pipeline readiness; `snapshot` writes
  honest `Inherited` rows; never invents ids; ratchet and lock are person actions it only recommends), the plan
  command and `plan-addendum.md` (brownfield: platform-scope NFRs for code the feature adds or changes).

## 3. Checks

| Check | Greenfield | Brownfield |
|---|---|---|
| `BASE-SKELETON` missing `required_paths` | error | not reported (1 info line per profile) |
| `BASE-SKELETON` missing `pipeline_paths` | error (part of required) | error (additive hint) |
| `BASE-ENV` git unusable | warn | error |
| `BASE-ENV` pin file UTF-16 / BOM | error | error |
| `BASE-CONFORMANCE` file missing | error | info (optional); error per enforced NFR |
| Platform NFR without a row | error / warn by level | info; error if enforced |
| `Inherited` | error | baseline snapshot: info (error if enforced); feature plan: error |
| `Gap` with remediation ref | error | warn; error if enforced |
| Duplicate NFR rows | error | error |
| `BASE-CONSTITUTION` I–IV | kit template | kit template |
| `BASE-CONSTITUTION` V–VIII | kit template | lock if present, else kit template |

## 4. Limits

- The gate does not look at which code a feature touches. Platform NFRs in a feature plan are guided by the
  prompt only; `PLAN-NFR-CONFORMANCE` still checks feature-scope NFRs only. Review and the ratchet are the control.
- `docs/adr` (`BASE-ADR-DIR`) is still required in brownfield; `ekit init` creates it.
- The lock and the ratchet file are plain files in the repository; `opencode.json` denies the agent the
  commands, not an edit of the files (`.ekit/*` is already denied to its edit tool). `by` is git `user.name`
  or `USER` / `USERNAME`, not authentication.
- Projects not marked `mode: brownfield` in `.ekit/project.yaml` behave exactly as in 0.5.1.
- The kit requires `ekit >=0.6.0,<0.7`: an older CLI would reject `Inherited`.
